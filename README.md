# BusFlow

BusFlow is a real-time transit operations platform for simulated bus fleets. It ingests imperfect GPS events, maintains live bus state, estimates arrivals, detects operational anomalies, and exposes measurable system behavior through APIs, WebSockets, logs, metrics, and load tests.

This project is being built as a serious engineering portfolio and B.Tech final-year project. The implementation will prioritize correctness, explicit design decisions, reproducibility, and measured results over superficial feature count.

## Project goals

- Build an event-driven real-time system rather than a map-only demo.
- Model duplicate, delayed, missing, invalid, and out-of-order GPS events.
- Compare a transparent ETA baseline with progressively improved models.
- Measure latency, throughput, consumer lag, API performance, and prediction error.
- Keep every major decision documented and reproducible locally.

## Initial technology direction

- Python, FastAPI, Pydantic, SQLAlchemy, Alembic
- PostgreSQL for durable relational and historical data
- Redis Streams for the first event-stream implementation
- React and TypeScript for the operator dashboard
- Pytest for unit and integration tests
- Locust for load testing
- Docker Compose for local reproducibility

The architecture will start as a modular monorepo with independently runnable services. We will only split services further when the boundary is justified by a real requirement or measurement.

## Development principle

Every completed session should leave behind a working slice, tests, documentation, and evidence of verification. Performance numbers will never be invented; they will be generated by repeatable load-test runs and recorded with their environment and configuration.
